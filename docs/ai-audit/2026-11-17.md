# AI Director audit and incremental verification — 2026-11-17

## Architecture and confirmed causes

The panel snapshots native editor state. LocalDirector calls the localhost-only
Next route, which uses the installed Ollama model with a scene-specific constrained
schema. The client parses and validates the complete reply, dry-applies it, and
allows one correction. The panel checks for concurrent edits and commits a single
undoable native document. CanvasEngine supplies decoded media/time;
compositeFrame draws layers. The WebCodecs exporter uses that same compositor.
There is no second canvas document or model-generated executable code.

Confirmed before this increment:

- The earlier missing `format` integration and underline rendering fixes were
  present in the staged diff. This increment did not recreate or revert them.
- Valid JSON still allowed unwanted constant X/Y tracks, which are offsets added
  to base position. A real static Hello request reproduced this in 93.9 seconds.
- Unselected layers lost geometry/style in the final model message, despite
  sceneForModel having collected those fields.
- Blur rendered only x/y/blur tracks while its AI schema advertised all tracks.
  Non-text layers also advertised text-only curve tracks.
- `drawIn` used horizontal scaling for brushes rather than path tracing.
- Up to three inference calls per request were allowed for capability lookup,
  with another request for correction. Timing/token data was discarded.
- Object identity alone caused scene conflicts after equivalent array replacements.
- Model discovery included nomic-embed-text, which cannot generate edits.
- General drawings have no native group transform. Repeating translation offsets
  preserves a composition; repeating rotation rotates each part about its OWN
  center. Arbitrary grouped rotation needs an explicit compiler or native grouping.

## Capability matrix (code inspection)

| Capability | Manual editor | AI adapter | Preview / WebCodecs export | Gaps |
|---|---|---|---|---|
| Text, bold/italic/underline, fill, shadow, gradient, stroke, curved text | Yes | Yes; advanced fields via inspect | Shared compositor | Text wrapping needs measured sizing; model placement still fallible |
| Rectangle, ellipse, regular polygon | Yes | Add/update/delete/move | Shared compositor | No subject shapes or subject templates |
| Open/closed brush, smooth curves, fill and stroke | Yes | Yes, normalized points | Shared brush geometry | Model must invent recognizable geometry |
| Brush progressive reveal | Preset | drawIn plus drawDuration | True arc-length tracing in this increment | Fill appears when path completes; curves sampled during reveal |
| Position, rotation, scale, opacity keyframes | Yes | Yes for rendered properties | Shared keyframe engine | Per-layer pivots, no group pivot |
| Blur region | Yes | Base properties and x/y/blur tracks | Shared compositor | Manual keyframe UI still offers extra ignored properties |
| Images | Import/edit | Existing-layer edits | Shared compositor | AI cannot import or generate media |
| Video | Import/edit/cut | Existing edits; split/trim normal-speed clips without effects | Shared compositor with decoded sources | Speed ramps and effects excluded from AI cutting |
| Audio | Linked media volume/mute/window | Volume/mute/delete/timeline move | Preview engine / export audio mix | No AI audio generation or fades |
| Transitions and animation presets | Larger preset list | Listed subset | Shared compositor | typewriter is a fade approximation; non-brush drawIn is a stretch |
| Chroma key, background removal, enhancement, captions, clip effects | Yes | Not exposed by Director | Existing relevant render/process paths | Separate tools; do not promise Director support |
| Grouping, arbitrary vector group transforms | No document group type | Not available | Per-layer only | Requires general representation/compiler work |
| Undo/redo, saved projects, timeline layers | Yes | One native transaction | Existing state | Browser regression verifies undo/redo; cloud save roundtrip not exercised |

FFmpeg fallback is a separate filter renderer: it omits shape/brush layers,
keyframes and clip effects and approximates some animation. It is NOT equivalent
to WebCodecs. No fallback rewrite was attempted in this increment.

## Changes in this increment

- Match generated and final validated keyframe properties to the renderer.
- Keep allowed native geometry/style for unselected layers, still excluding URLs.
- Reject redundant constant multi-key tracks on newly added layers and use the
  existing one-correction path. Existing static single keys remain compatible.
- Add a general arc-length brush reveal over existing smooth/open/closed geometry.
  No cat, face, house or other subject geometry is defined in application code.
- Limit capability lookup to one round; remove inspect from the second decoder.
- Expose common text properties first. A model-selected text inspection restores
  all advanced fields; no user-prompt keywords select tools or artwork.
- Add structured inference metrics to the stream and development console.
- Compare document values for conflicts, preserving media-object identity checks.
- List only installed local models with completion capability; check again on POST.

## Verification and limitations

The deterministic browser fixture uses native text and brush operations. At t=0,
0.75,1.5,3,4.5 its green text centroid is 159.108,234.108,309.108,459.108,459.108.
Blue stroke pixels are 0,1252,2452,4849,4849. Thus the text moves exactly 300px,
and the stroke reveals progressively and holds. Actual midpoint PNG inspected:
green bold underlined Hello and a partially traced blue line. Canvas and
OffscreenCanvas output matched exactly at all five times.

A separate real UI test applied that fixture, undid the entire batch, redid it,
and exported H.264 at 1280×720 / 30fps without page errors. Encoded-frame comparison
results are recorded separately. This is renderer/transaction evidence, NOT proof
that Qwen understood the fixture prompt.

Browser probes use an isolated guest context. The export probe intercepts the AI

native validation. Screenshots of a replay must not be described as a new inference.

## Measured live requests

All requests used the installed Qwen2.5:7b, Q4_K_M, 8192-token context,
temperature zero, CPU inference (reported VRAM usage zero). No model substitution.

| Case | Result | Elapsed | Inferences | Prompt / generation | Output tokens |
|---|---|---:|---:|---:|---:|
| Baseline green bold underlined Hello | Unrequested constant X/Y offsets | 93.9s | 1 | Not instrumented | — |
| Expanded instructions | Still unwanted offsets/shadow | 111.8s | 1 | 45.1s / 65.8s | 178 |
| Compact first test | Invalid opacity, correction also invalid | 112.5s | 2 | See probe metrics | 65 + 135 |
| Exact laughing cat / moving rotating tongue | Valid JSON, visually WRONG | 278.2s | 1 | 1.79s / 275.69s | 795 |
| Text after explicit ranges/color, clean warm route | Correct green bold underline, no motion | 20.44s | 1 | 0.224s / 19.933s | 70 |

The final text prompt contained 2,855 characters; decoder schema 7,580 characters;
model reported 621 input tokens. Dry validation/application took ~2ms; application
alone ~0.09ms. No capability inspections or corrections were needed in the clean
warm success. This is not a statistically meaningful correction-rate benchmark.
Earlier invalid opacity results were 100 then 50; numeric schema bounds were
checked by the native validator but were not enforced by the decoder. Correction
messages now include the exact allowed range and received number. New text must
choose a textColor in the decoder, preventing the observed omitted-color case.

One probe straddled Next dev hot reload: its initial request used the old prompt,
and its correction used the new one. That 65.8s mixed-version result is excluded
from the clean comparison. Final success was repeated on the fully compiled route.

## Remaining work / exact next steps

1. Prototype a SMALL, model-generated scene representation for complex drawings:
   named parts, shared normalized object bounds, each part's primitive/path, local
   placement, and independent motion. Compile that deterministically to these
   existing native layers. No subject-specific generators. Keep direct native
   operations for simple text/media edits; avoid a mandatory second model call.
2. Add geometry preflight on the temporary document: wholly off-canvas parts,
   degenerate contours, static tracks presented as motion, and consistent group
   pivots. Do not silently clamp or replace model geometry. Current checks still
   allow single static keys and cannot tell a circle from a requested cat.
3. Benchmark the same difficult prompts through that compiler, inspect all frames,
   and report failures. Merely renaming ellipses as ears/tongue will not suffice.
4. A 795-token drawing at the measured ~2.9 tokens/sec already needs ~275 seconds
   for generation. A 20-second target requires a much shorter representation or
   faster inference hardware, not more prompt prose. Cold prompt processing was
   ~16–17 tokens/sec in measured runs; the 20.4s text result used cached context.
5. Address the separately documented FFmpeg fallback gaps before promising export
   parity on browsers without WebCodecs. Add cloud save/reload integration coverage.

No dependency additions, external AI service, subject hardcodes, model switches,
second document state, or deployment were introduced in this increment.
